Booklat - Library Management System

A mobile-first, open-source library management system built for schools and small organizations. Features a custom user model with LRN-based authentication, DB-driven role-based permissions, copy-level inventory tracking, and an immutable audit log.
Built with Django 5.1, PostgreSQL 16, Redis 7, Celery, and a custom CSS design system — no Django admin, no frontend frameworks.

Live Demo

Project Overview

Introduction

     Booklat is a mobile-first, open-source library management system designed from the ground up for schools and small organizations. It provides complete lifecycle management of a library: from cataloging books and tracking physical copies, to managing member checkouts, returns, and requests — all backed by an immutable, append-only audit trail. The system is built as a single Django 5.1 monolith with 9 domain-specific apps, a custom user model, DB-driven permissions, and a handcrafted CSS design system with dark mode support.

Challenges

⏺ Custom User Model & Auth: Building a non-AbstractUser custom model with Argon2id hashing, LRN-based authentication, and DB-driven role permissions — bypassing Django's built-in auth entirely.
⏺ Append-Only Audit Trail: Designing an immutable JSONField-based audit log that records every action across the system without modification or deletion.
⏺ Fine-Grained Permissions: Implementing a custom permission system where roles define granular access (e.g. "loans.create", "inventory.archive") checked at the view level via decorators.
⏺ Copy-Level Inventory Tracking: Each book can have multiple physical copies with distinct statuses (Available, Borrowed, Reserved, Lost, Damaged), each with its own history.
⏺ Mobile-First Without Frameworks: Building a responsive UI with app shell layout (sidebar + topbar + bottom nav), dark mode, and touch-friendly interactions using only vanilla CSS.

Solution

     Booklat replaces Django's admin entirely with custom management views. The account system uses an LRNAuthenticationBackend for login (LRN + password), with role-based permissions stored in Permission and RolePermission database tables. Every action — from checkouts and returns to inventory status changes — is recorded immutably in the audit app via the `log_action` utility. Physical copies are tracked with the BookCopy model with 7 status choices, and CopyHistory preserves an append-only timeline per copy. A global login middleware protects all URLs, and a must-change-password enforcement ensures new users update their credentials. The entire system runs in Docker Compose with PostgreSQL + Redis + Celery + Gunicorn.

Key Features

✔ Nine Domain-Specific Apps: accounts, books, inventory, loans, requests_app, audit, dashboard, core, freedom_wall.
✔ LRN-Based Authentication: Login via LRN + password, Argon2id hashing, 16-char minimum password rules.
✔ DB-Driven Role Permissions: 3 default roles (Administrator, Staff, Member), custom permission decorators.
✔ Copy-Level Inventory: Each book has individual copies with status tracking and append-only history.
✔ Checkout/Return Workflows: Full loan lifecycle with overdue tracking and soft-delete semantics.
✔ Checkout Requests: Members can request books; staff approve or reject with notes.
✔ Immutable Audit Log: JSONField metadata, append-only — every system action is traceable.
✔ Freedom Wall: Sticky-note posts with upvotes, pending moderation queue, Celery midnight purge.
✔ CSV Bulk Operations: Import/export books, members, and inventory via CSV.
✔ Mobile-First Design System: Custom CSS with dark mode, app shell layout, touch-friendly controls.
✔ Docker-Compose Deployment: PostgreSQL 16 + Redis 7 + Celery + Gunicorn with optional Cloudflare Tunnel.
